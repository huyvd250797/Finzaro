# Finzaro V0.7.5 — Release Stabilization

V0.7.5 freezes the feature set and establishes a stable baseline before the Release Candidate. It does not introduce a new user-facing module.

## What changed

- Fixed calculator state when the user changes an operator before entering the next operand.
- Made overlay scroll locking reference-counted so nested modal/bottom-sheet states do not unlock the page too early.
- Hardened PWA service-worker installation: required recovery pages remain mandatory, optional icon caching can no longer abort installation, and activation only removes Finzaro-owned caches.
- Kept the mobile taskbar fixed and safe-area aware, with the full center `+` control visible.
- Kept all money inputs on the shared calculator and canonical numeric storage path.
- Added database indexes for existing user-scoped Loan Payment, Credit Card Payment and Asset Valuation history queries.
- Pinned direct npm dependency versions in `package.json` to reduce accidental release drift.

## Database upgrade

If the database is already on V0.7.1 or later, run:

`supabase/sql-editor/V0.7.5_release_stabilization.sql`

Then optionally run:

`supabase/sql-editor/V0.7.5_release_stabilization_verify.sql`

The V0.7.5 SQL is idempotent (`create index if not exists`) and does not alter existing financial records.

## Release checks

Before production deployment, run:

```bash
npm install
npm run lint
npm run typecheck
npm run test
npm run build
```

For Supabase CLI environments, also run database lint/tests against an isolated environment before pushing migrations.
