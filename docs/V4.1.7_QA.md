# Finzaro V4.1.7 — QA / CI portability

## Root cause

Two historical tests used absolute global paths built from `process.execPath` to load TypeScript. They loaded on the developer's Node installation but not on the Vercel Node installation. A failed file-level test registers only one failing suite, not its subtests, explaining the reported decrease from 206 tests to 201 tests with two failures.

## Reproduction evidence

A separate copy of the Node 22 executable was placed at another absolute path with no global TypeScript in its neighboring `lib/node_modules` directory. `typescript` was available in the application's `node_modules` as it is after `npm install` on Vercel.

| | V4.1.6 | V4.1.7 |
|---|---|---|
| Node test count | 201 | 209 |
| Passed | 199 | 209 |
| Failed | 2 (file loaders for V4.1.2/V4.1.3) | 0 |
| TypeScript import | absolute global path | `createRequire(import.meta.url)("typescript")` |

## Scope

- Application business logic and calculations are byte-for-byte unchanged.
- No additional dependencies: TypeScript 5.9.3 already exists in `devDependencies`.
- No Supabase SQL changes; no migration required.
- New tests: `tests/v417-portable-test-runner.test.mjs` (3 cases).
- Release gate remains strict; does not exclude failing tests or bypass build errors.

## Production requirements

Running `npm run check` with all npm dependencies and environment variables is required on Vercel/staging. Passing these 209 Node tests is insufficient to certify Next.js build/runtime, which was not verified in the offline packaging environment.
