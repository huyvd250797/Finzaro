# Finzaro V0.0.3 — Account Core Setup

This release assumes the V0.1.1 foundation and V0.0.2 Authentication are already working.

## 1. Run the Account Core SQL

Open:

```text
Supabase → SQL Editor → New query
```

Copy all content from:

```text
supabase/sql-editor/V0.0.3_account_core.sql
```

Paste and click **Run**.

Do not rerun `20261005110000_foundation_environment.sql` if it was already applied.

## 2. Verify the database

In Table Editor you should see:

```text
accounts
```

Expected account types:

```text
cash
bank
ewallet
savings
```

Optional: run:

```text
supabase/sql-editor/V0.0.3_account_core_verify.sql
```

You should see the `accounts` columns and four RLS policies.

## 3. No new ENV variables

Keep the existing Vercel variables from Authentication:

```dotenv
NEXT_PUBLIC_FINZARO_ENV=development
NEXT_PUBLIC_SITE_URL=https://your-finzaro.vercel.app
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxx
```

## 4. Deploy

Push V0.0.3 to the same GitHub repository and let Vercel redeploy.

## 5. Functional test

After login:

```text
/accounts
```

Create:

```text
Name: Vietcombank
Type: Bank
Currency: VND
Balance: 10000000
```

Expected result:

- account appears immediately;
- `/overview` shows 10,000,000 VND as the real account total;
- editing updates the account;
- archiving removes it from the active Dashboard total;
- restoring returns it.

## 6. Multi-user RLS test

Create a second user. The second user must not see the first user's accounts.

The application additionally filters mutations by `user_id`, but RLS is the final database authorization boundary.

## 7. Balance semantics in this release

V0.0.3 has no transaction ledger yet, so editing the balance updates both opening and current balance.

V0.0.4 will introduce Transaction Core and take over balance movement from normal account editing.
