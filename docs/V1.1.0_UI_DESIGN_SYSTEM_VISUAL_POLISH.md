# Finzaro V1.1.0 — UI Design System & Visual Polish

## Scope

V1.1.0 is the first UI/UX-focused release after the production baseline. It does not introduce a new top-level finance module. The scope is shared visual consistency, faster/readable Reports and completion of the existing Savings/Goal transfer relationship.

## Savings transfer + Goal

On `Giao dịch → Chuyển tiền`, when the destination Account is a Savings account, Finzaro exposes **Thêm vào mục tiêu**.

- The Goal must be active and use the same currency as the Savings account.
- If the Savings account already has an active linked Goal, only that linked Goal is eligible, preventing conflicting Goal allocation.
- If the selected Goal is already linked to the destination account, the existing transfer-goal synchronization handles the contribution and the V1.1.0 RPC does not insert it twice.
- For a compatible unlinked Goal, the V1.1.0 RPC inserts a contribution entry after the financial transfer is created.
- Both operations execute in one PostgreSQL transaction; any failure rolls the whole operation back.
- Existing transaction deletion continues to reverse Account balances and remove Goal entries through the existing rollback path.

## Reports UX

### Overview

- `Chi tiêu`, `Thu nhập`, `Ròng` stay on one compact 3-column KPI row on mobile and desktop.
- Category composition is a full pie, not a donut with a center card.
- Selecting a slice or legend item displays Category, percentage and formatted amount.
- Slices at or above the large-slice threshold label themselves directly inside the pie.

### Calendar

- Small screens use a horizontally scrollable calendar canvas instead of shrinking seven columns until amounts become unreadable.
- Day cells have a larger minimum height.
- Income is green and Expense is red.
- Both can be visible for the same day.
- `0đ` values are intentionally omitted.

### Loading/performance

Reports use `loadReportLedger`, a dedicated paginated loader. Transactions/currencies load in parallel, and Accounts/Categories are fetched only on report surfaces that need them. A route loading skeleton reduces perceived waiting time during navigation.

## Visual system

V1.1.0 centralizes commonly reused design primitives in `app/globals.css` and shared UI components:

- raised/soft surface tokens;
- shared card/control radius;
- shared card shadow;
- semantic success/warning/danger values;
- consistent focus-visible outline;
- touch feedback and reduced-motion behavior;
- shared `fin-card`, input and button treatment.

## Deployment checklist

1. Deploy the V1.1.0 source.
2. Apply `V1.1.0_ui_design_system_visual_polish.sql` once to the target Supabase project.
3. Run the V1.1.0 verification SQL.
4. Test Savings transfer without Goal.
5. Test Savings transfer with a compatible unlinked Goal.
6. Test Savings transfer into an account already linked to a Goal and verify progress increases once, not twice.
7. Delete a test transaction and confirm Account/Goal rollback.
8. Verify Reports Calendar on a narrow iPhone/PWA viewport.
9. Verify pie click/tap behavior and the 3-KPI row.
10. Run the standard production build/check pipeline in the deployment environment.
