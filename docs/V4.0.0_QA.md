## Manual acceptance cases (must pass on staging before production)

- [ ] 320px, 375px, 390px, 430px iPhone widths: all main navigation items, balance/KPI, report labels and transaction action buttons are reachable without horizontal page overflow.
- [ ] Open expense/income/transfer form, select >4 rows of categories, swipe the form up/down; Save and Cancel stay reachable even with iOS keyboard open.
- [ ] Enter amount 0 or blank: an inline alert appears in the visible sheet, no RPC called; positive value is accepted only after standard server validation.
- [ ] Open money calculator, tap quickly/hold/drag/cancel; 114% tactile response does not obscure/activate other keys and reduces under `prefers-reduced-motion`.
- [ ] Trigger invalid required account/title: native invalid field is scrolled into view in the overlay, no background document scroll.
- [ ] Save once, retry on simulated server rejection; no duplicated transaction or false success; rollback and error feedback remain correct.
- [ ] Copy transaction across dates: preserve date source/target colors and idempotent RPC; no duplicate records on retry.
- [ ] Delete a transaction with simulated RPC error: previously hidden row returns without changing the account balance.
- [ ] Open/close nested calculator and transaction sheets: proper body locking, focus management, Escape, Tab and visualViewport sizing.
- [ ] Return from Reports to Calendar with selected day/month and scroll. No full-page splash during tab navigation; only route skeleton if relevant uncached content is still streaming.
- [ ] Toggle Thu/Chi in the same report period without new report fetch. Compare correct totals before and after.
- [ ] Toggle theme via OS and user button; light/dark text and chart colors remain readable. Test high contrast and reduced motion.
- [ ] Check report vs CSV/XLSX/PDF figures and transfers/multi-currency exclusions. No database migration required for V4.
- [ ] Validate login, logout, offline fallback, error/retry and use of back/forward navigation on mobile and desktop.

## Performance targets (NOT measured results)

- Input response <100ms on supported test devices.
- Previously-loaded report type toggle without request; route navigation without full-page loading flashes.
- Main action reachable at 320px width with keyboard expanded.
- LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 on representative devices measured with p75.
- Manual 1k/5k/10k transaction history and reports stress test; collect p50/p95 requests and scroll frame behavior.

If these fail, **do not** label this build production-ready. Record browser/device, viewport, route, repro steps, screenshots and logs.
