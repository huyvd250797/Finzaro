# Finzaro V0.0.7 — Recurring Transactions & Financial Calendar

## Mục tiêu

V0.0.7 bổ sung quản lý giao dịch định kỳ và lịch tài chính. Lịch dự kiến **không làm thay đổi số dư** cho tới khi người dùng xác nhận kỳ đó là `Đã thanh toán` / `Đã nhận`. Khi xác nhận, PostgreSQL gọi Transaction Core V0.0.5 để tạo transaction + ledger entries thật và cập nhật số dư atomic.

## SQL Editor

1. Mở Supabase → **SQL Editor** → **New query**.
2. Copy toàn bộ file `supabase/sql-editor/V0.0.7_recurring_calendar.sql`.
3. Bấm **Run**.
4. Có thể chạy `supabase/sql-editor/V0.0.7_recurring_calendar_verify.sql` để kiểm tra read-only.

Không chạy lại migration V0.0.3–V0.0.6 nếu database DEV đã có các phiên bản đó.

## Database mới

- `recurring_rules`: template income / expense / transfer định kỳ.
- `recurring_occurrences`: lưu các kỳ đã `paid` hoặc `skipped`.
- `post_recurring_occurrence_v007(...)`: xác nhận kỳ và tạo Transaction thật nếu paid.
- `undo_recurring_occurrence_v007(...)`: hoàn tác kỳ; nếu kỳ đã tạo Transaction thì transaction đó được reverse qua Transaction Core.

RLS đảm bảo user chỉ đọc/ghi rule và occurrence của chính mình. Client không được insert trực tiếp vào `recurring_occurrences`; lifecycle kỳ định kỳ đi qua RPC để giữ tính toàn vẹn ledger.

## Chu kỳ hỗ trợ

- Weekly
- Monthly
- Yearly
- `interval_count` cho phép mỗi N tuần / tháng / năm.
- Monthly schedule dùng ngày bắt đầu làm anchor và tự clamp ngày cuối tháng (VD 31/01 → 28/29/02 → 31/03).

## Performance / UX trong V0.0.7

V0.0.7 đồng thời xử lý phản hồi chậm:

- `requireUser()` dùng React `cache()` để deduplicate auth check trong cùng request.
- Chỉ dùng verified `getClaims()` thay vì gọi tiếp `getUser()` cho mỗi render server.
- Tạo account và mở Transaction composer có local instant reveal, không cần chờ server round-trip chỉ để hiện form.
- Dashboard có navigation progress + route loading skeleton.
- Các nút submit quan trọng dùng `useFormStatus()` và đổi label ngay: `Đang đăng nhập...`, `Đang tạo tài khoản...`, `Đang lưu giao dịch...`, v.v.

## Smoke test sau deploy

1. Tạo recurring expense `Tiền nhà`, monthly, ngày hôm nay.
2. Mở `/recurring` và kiểm tra lịch hiển thị khoản đến hạn.
3. Bấm `Đã thanh toán`.
4. Kiểm tra `/transactions`: transaction mới xuất hiện.
5. Kiểm tra `/accounts`: số dư nguồn giảm đúng.
6. Kiểm tra `/budgets`: Actual Spending của category tương ứng tăng đúng.
7. Quay lại `/recurring` → bấm `Hoàn tác` và xác nhận transaction/số dư được reverse.
8. Kiểm tra Login/Register/Create Account: nút phải chuyển sang trạng thái `Đang...` ngay sau click.
