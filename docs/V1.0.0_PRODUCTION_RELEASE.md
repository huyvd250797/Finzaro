# Finzaro V1.0.0 — Production Release

V1.0.0 freezes the existing finance feature set and promotes the V0.8.0 Release Candidate to the first production baseline. No new finance module is introduced in this release.

## Production hardening

- Central application version is `1.0.0` / `Production Release`.
- Dependency ranges are pinned to exact versions in `package.json` to reduce unexpected deploy drift.
- `prebuild` validates the public Supabase environment before Next.js production compilation.
- Production security headers now include anti-framing, COOP, HSTS, MIME-sniffing protection, referrer policy and a restrictive permissions policy.
- Root, dashboard and global error boundaries provide deterministic recovery instead of a blank/Next.js error surface.
- A custom 404 screen returns users to Overview.
- Service-worker behavior remains conservative: authenticated HTML is network-only and only Finzaro static/recovery assets are cached.

## Data integrity

- Reports, calendar drill-down and CSV export now request the complete selected date range instead of silently stopping at 10,000 transactions.
- The paginated report loader has a 100,000-transaction safety ceiling; exceeding it fails visibly rather than returning incorrect totals.
- Category historical-usage counts are paginated instead of being silently capped at 10,000 rows.
- Standard Income remains the only income included in financial reports; Loan/Credit Card funding remains excluded from real income.
- Existing atomic Transaction/Loan/Credit Card/Savings RPC flows are preserved.

## Database

V1.0.0 does **not** mutate the database schema. If V0.8.0 has already been applied, no new migration is required.

Run the production verification script after confirming all prior migrations are present:

`supabase/sql-editor/V1.0.0_production_release_verify.sql`

The script checks core tables, RLS, transaction RPCs, production indexes and the V0.8.0 category-icon constraint. It does not modify financial data.

## Production deploy checklist

1. Confirm V0.8.0 database migration is already applied.
2. Run `V1.0.0_production_release_verify.sql` in Supabase SQL Editor.
3. Configure Vercel environment variables from `.env.example`.
4. Use `NEXT_PUBLIC_FINZARO_ENV=production` for the Production environment.
5. Use an HTTPS `NEXT_PUBLIC_SITE_URL` matching the production domain.
6. Keep SSI FastConnect credentials server-only if market-data sync is enabled.
7. Run `npm install`, then `npm run check` in a dependency-complete environment.
8. Deploy to Vercel and verify Login/Register/Reset Password redirect URLs in Supabase Auth settings.
9. Smoke-test Account, Transaction, Transfer, Credit Card payment, Loan payment, Savings transfer, Reports Calendar and PWA update flow.
10. Keep the V0.8.0 package available as the immediate rollback source until V1.0.0 has been validated in production.

## Post V1.0 roadmap

After this release, source changes must increment the version. The planned line is UI/UX-first rather than feature-first: V1.1.0 Design System & Visual Polish, V1.2.0 Mobile UX Optimization, V1.3.0 Transaction UX Redesign and subsequent interaction/performance releases.
