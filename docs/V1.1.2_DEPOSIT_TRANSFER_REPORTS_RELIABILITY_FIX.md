# Finzaro V1.1.2 — Deposit Transfer & Reports Reliability Fix

V1.1.2 fixes two regressions that remained after V1.1.1.

## Root causes

- The **Tiền gửi** module stores fixed-term savings in `public.deposits`; it is not the same entity as `accounts.account_type = 'savings'`. V1.1.0/V1.1.1 targeted the wrong destination model, so Deposit records could never appear as actual Transfer destinations.
- Reports still depended on the embedded PostgREST hydration path used by the shared ledger loader. On affected deployments this could throw at server render time and fall through to the generic dashboard error boundary.

## Fixes

- Transfer now loads active records from `public.deposits` and exposes them in **Nơi nhận tiền** under the Tiền gửi module group.
- `create_deposit_transfer_v112` atomically decreases the source Account, increases `deposits.principal_minor`, and optionally adds a contribution to an existing same-currency Savings Goal.
- `deposit_funding_events` stores rollback metadata. `delete_financial_transaction_v112` reverses Account, Deposit and the exact Goal contribution when the transaction is deleted.
- Reports use paginated `report_flow_rows_v112` rows instead of embedded relations. If the RPC has not been installed yet, the app falls back to a relation-free transactions + chunked entries loader rather than the failing embedded path.
- Reports now has a route-specific recoverable error boundary.

## Required Supabase migration

Run once after the V1.1.0 migration:

`supabase/sql-editor/V1.1.2_transfer_deposit_reports_reliability.sql`

Then run the read-only verification:

`supabase/sql-editor/V1.1.2_transfer_deposit_reports_reliability_verify.sql`

## Smoke test

1. Open **Giao dịch → Chuyển tiền**.
2. Confirm active items from **Tiền gửi & lãi suất** are visible under **Nơi nhận tiền**.
3. Select a source Account with the same currency, choose a Deposit, optionally enable **Thêm vào mục tiêu**, and save.
4. Confirm the source Account decreases, Deposit principal increases, and the selected Goal increases exactly once.
5. Delete the transfer and confirm all three values roll back.
6. Open **Báo cáo → Tổng quan / Lịch / Phân tích** and confirm historical ledger data loads.
